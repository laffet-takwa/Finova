# Screenshots

This directory holds the screenshots embedded in the root `README.md`.

## Regenerating

```bash
cd frontend
npm run dev          # mock mode is the default, no backend needed
# in a second shell, from the repository root:
npm install          # installs puppeteer (dev tooling only)
node scripts/capture-screenshots.mjs                                    # desktop  -> docs/screenshots
node scripts/capture-screenshots.mjs --mobile --out=docs/screenshots/mobile  # mobile
```

Options: `--url=` (default `http://localhost:5173`), `--out=`, `--only=dashboard,fraud`.

The script signs in as `takwa@finova.dev` for customer routes and
`admin@finova.dev` for `/admin/**` — the router guards redirect otherwise, which
would silently capture a login page instead. It reports any console error it
sees, so a screenshot can never quietly hide a runtime failure.

question everything else alongside it.

## Why these are committed

Unlike most portfolio repositories, these images are committed rather than
regenerated by the reviewer, because the point of a screenshot section is to let
someone decide whether to look at the code. They are captured from a live run
against the mock data layer, so what they show is the actual product, not a
mock-up.
